# PunishedK Profile v2 — Setup

This folder contains a complete GitHub profile README, two vector assets, and two GitHub Actions workflows.

## Files

- `README.md` — public profile, backend/fullstack positioning, projects, metrics and snake
- `assets/hero.svg` — bespoke static header artwork
- `assets/metrics.svg` — API-generated counts (initially shows `—` pending sync)
- `scripts/update_stats.py` — dependency-free GitHub API collector and SVG renderer
- `.github/workflows/profile-stats.yml` — daily and manual refresh; commit on changed metrics only
- `.github/workflows/contribution-snake.yml` — daily and manual snake generation in the `output` branch

## Install using Git

In a clone of `https://github.com/PunishedK/PunishedK`, copy *all* the contents of this folder (including the hidden `.github` folder). Run:

```bash
git status --short
git add README.md assets/hero.svg assets/metrics.svg scripts/update_stats.py .github/workflows/profile-stats.yml .github/workflows/contribution-snake.yml .gitignore
git commit -m "feat(profile): create minimal developer portfolio"
git push origin main
```

Do not stage unrelated files. You can also upload files through the GitHub website while preserving directory paths, including `.github/workflows/...`.

## Run the workflows

On GitHub: repository → **Actions** → **Update Developer Profile Stats** → **Run workflow**. Then run **Generate Contribution Snake**. The snake image will not display until the `output` branch has been generated by its first successful run.

If push fails with `403 Resource not accessible by integration`, visit **Settings → Actions → General → Workflow permissions**, choose **Read and write permissions**, and save. Repository or organization policies can override this setting.

## Include private repository PRs

By default, the generated `GITHUB_TOKEN` can only access this profile repository and public GitHub data, **not** unrelated private repositories. To include private PRs:

1. Create a GitHub Personal Access Token (fine-grained recommended) owned by the account that can read the target private repositories; select the relevant repositories and grant **Pull requests: Read**. The token must be allowed to search the target repositories (organizational approval may also be required). A classic PAT with `repo` scope works too, but has broader access.
2. Go to the profile repository **Settings → Secrets and variables → Actions → New repository secret**.
3. Name the secret exactly `PROFILE_STATS_TOKEN` and paste the token. **Never commit or paste tokens into repository files.**
4. Re-run **Update Developer Profile Stats**. The SVG will report **TOKEN-VISIBLE PRS**, not an unqualified global total, because token visibility may be restricted. Only aggregate numbers are written to the public SVG.

GitHub API queries:
- `is:pr author:PunishedK` — authored PRs, regardless of merge state, visible to the token
- `is:pr author:PunishedK is:merged` — merged authored PRs visible to the token
- `GET /users/PunishedK` → `public_repos` — public repositories, including public forks

No PR records, private repository names, titles, or details are written to the output assets. The script deliberately refuses to overwrite stats if an API request fails or results are incomplete.

## Update without fake activity

- Metrics task checks daily but **commits only if numeric values or the visibility label change**.
- Snake is sourced from GitHub's contribution graph; no fake contributions are created.
- The output-branch snake updates are generated artifacts, not developer coding contributions.
- Stats SVG contents contain no clock timestamp, so date changes cannot manufacture a daily commit.

## Customization

Change the tagline, featured projects, and technology list in `README.md`. Adjust design colors in `assets/hero.svg` and `scripts/update_stats.py` (SVG renderer). Keep the username and output paths consistent if copying this setup to another account.
